Support Nodes are folders used to store files and directories that are directly related to the current level.
It's purpose is provide support to the user with additional data from itself.

Each Support Node uses a prefix in capitals followed by a dot e.g. `REV.Development`, `RES.Brand-Assets`, `TPL.Video-Project`.

| Prefix | Type | Purpose |
|---|---|---|
| `REV.` | Review | Get any loose files until they are sorted. |
| `RES.` | Resources | Shared resources for the parent's content. |
| `TPL.` | Templates | Starting structures for new workboards. |
| `00.` | Outcomes | Save deliverables of their siblings workboards. |

## REV. Review Folder
This [node (folder)](/en/foundationals/core-concepts#nodes) may contain all of your files and directories that are unsorted, as temporary sandbox for avoiding mess and maintaining the sort the level.  

> <h5> Naming Convention: </h5>
> Use the prefix « **REV.** » and inherit its parent's name.
> 
> e.g. `REV.Digital-Art`, `REV.Video-Edition`, `REV.Development`

> <h5> Naming Convention: </h5>
> Use the prefix « **TPL.** » and name what it starts.
>
> e.g. `TPL.Video-Project`, `TPL.React-Project`

## 90.Resources Folder
Its should have identifier **90**.  
This [node](/en/foundationals/core-concepts#nodes) (folder) serves as a centralized repository for frequently accessed reference materials, reusable assets, and static support files. It houses essential resources that remain consistently valuable across multiple projects or operations.

<h5> Naming Convention: </h5>
This node appears as `90.Resources-of-` and continue inherit their name from parent node.

```ansi {2}
[32m 📁[37m 02.Video-Edition                     [35m  ←−−− Parent
[32m  ├── 📁[37m 90.Resources-of-Video-Edition   [35m  ←−−− Resources Folder
[32m  │    ├── 📁[37m 01.Templates-and-presets
[32m  │    ├── 📁[37m 02.Music-and-SFX
[32m  │    ├── 📁[37m . . .
```

<h5> Utility </h5>
Functions as an **always-available toolkit** for your projects, tasks or homework. It provides a place to store frequently used files, templates, and resources that are accessible from current level.

## (00) Done Folder
Its should have identifier **00**.  
This [node](/en/foundationals/core-concepts#nodes) serves exclusively as the **final archive** for completed outputs. When a [workboard folder](/en/foundationals/workboard-nodes) reaches end-of-life after project/task completion, only the finalized assets are preserved here.

<h5> Naming Convention: </h5>
Always it should appears as **00.Done** at every level where workboards exist.  
if that you want, you may name it whatever you want but need to use the prefix **00.** before the name.

```ansi {2}
[32m 📁[37m 02.Video-Edition                      [35m ←−−− Parent
[32m  ├── 📁[37m 00.Edition-Portfolio             [35m ←−−− Done Folder
[32m  │    ├── 📁[37m 01.Templates-and-presets
[32m  │    ├── 📁[37m 02.Music-and-SFX
[32m  │    ├── 📁[37m . . .
```

## Temporal Folders (~)
Alright, thats not a identifier as such, it's just a mark.  
This special marker (not a numbered identifier) designates **ultra-short-lived storage** for active work files. Unlike the structured [REV. Review Folder](#rev-review-folder), `~` nodes are disposable containers for assets during active manipulation, serving as temporary holding areas that should be deleted immediately after use.

<h5> Naming Convention: </h5>
Always prefixed with `~` and continue with any name you want.
