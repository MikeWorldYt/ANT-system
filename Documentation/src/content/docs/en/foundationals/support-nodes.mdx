Support Nodes are folders used to store files and directories that are directly related to the current level.
It's purpose is provide support to the user with additional data from itself.

Each Support Node uses a prefix in capitals followed by a dot e.g. `REV.Development`, `RES.Brand-Assets`, `TPL.Video-Project`.

| Prefix | Type | Purpose |
|---|---|---|
| `REV.` | Review | Get any loose files until they are sorted. |
| `RES.` | Resources | Shared resources for the parent's content. |
| `TPL.` | Templates | Starting structures for new workboards. |
| `00.` | Outcomes | Save deliverables of their siblings workboards. |

## REV. Review Folder
This [node (folder)](/en/foundationals/core-concepts#nodes) may contain all of your files and directories that are unsorted, as temporary sandbox for avoiding mess and maintaining the sort the level.  

> <h5> Naming Convention: </h5>
> Use the prefix ` REV. ` and inherit its parent's name.
> 
> e.g. `REV.Digital-Art`, `REV.Video-Edition`, `REV.Development`

## RES. Resources Folder
This [node (folder)](/en/foundationals/core-concepts#nodes) holds content ready to use while projects are running, for example client assets (logos, images, etc) or project presets. 

its content dotn need be copied into a project: may use it direclty from here. Each `RES.` folder holds one kind of content, so a level can have several Resources (`RES`).

> <h5> Naming Convention: </h5>
> Use the prefix ` RES. ` and name what it holds.
>
> e.g. `RES.Client-Assets`, `RES.Edition-Assets`
>
> At level 1, `900.Resources` stays unchanged.

```ansi {2,5}
[32m 📁[37m 04.Video-Edition                           [35m←−−− Parent
[32m  ├── 📁[37m RES.Client-Assets                     [35m←−−− Resources of the clients
[32m  │    ├── 📁[37m Logos

[32m  ├── 📁[37m PJ.133_Promo-Video                    [35m←−−− Uses them from RES, without copying
[32m  └── 📁[37m PJ.134_Product-Launch                 [35m←−−− Uses them from RES, without copying
```

## (00) Outcomes Folder
This [node (folder)](/en/foundationals/core-concepts#nodes) receives the deliverables of the [workboards](/en/foundationals/workboard-nodes) beside it.

When a workboard is finished, [FolderManager](/en/folder-manager/project-management#outcomes) moves its deliverable here into a dated folder and leaves a shortcut in the workboard to find it again.

> <h5> Naming Convention: </h5>
> Use the identifier ` 00. ` and any name you want, at every level where workboards exist.
>
> e.g. `00.Outcomes`, `00.Edition-Portfolio`

```ansi {2-4}
[32m 📁[37m 04.Video-Edition                           [35m←−−− Parent
[32m  ├── 📁[37m 00.Outcomes                           [35m←−−− Outcomes Folder
[32m  │    └── 📁[37m (26-11-01)_Promo-Video           [35m←−−− Dated delivery
[32m  │         └── 📄[37m Promo-Video-Final.mp4
[32m  └── 📁[37m PJ.133_Promo-Video                    [35m←−−− Workboard
[32m       ├── 📁[37m 01.RawFootage
[32m       └── 📁[37m 04.Renders                       [35m←−−− Output folder
[32m            └── 📄[37m (26-11-01)_Promo-Video.lnk  [35m←−−− Shortcut to the delivery
```

## Temporal Folders (~)

This prefix is `~` is used for temporary files; It's placed at the start of the name of any folder or file and [FolderManager](/en/folder-manager/folder-manager) ignores it, no sort, no rename or other automation actions.

Only use it to mark temporary items that should be deleted afterwards, so they don't keep consuming space.

> <h5> Naming Convention: </h5>
> Place a tilde ` ~ ` at the start of the name of any folder or file.
>
> e.g. `~09585`, `~render-draft.mp4`


```ansi {4, 6}
[32m 📁[37m 04.Parent-example                 
[32m  ├── 📁[37m 01.Child-sorted                
[32m  ├── 📁[37m 02.Another-file-sorted    
[32m  ├── 📁[37m ~09585                                [35m←−−− Temporary folder
[32m  ├── 📄[37m common-file.txt
[32m  └── 📄[37m ~reference-document.docx              [35m←−−− Temporary file


```
