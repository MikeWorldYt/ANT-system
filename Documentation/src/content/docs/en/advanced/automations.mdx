Automations tidy the loose files that land in a node folder, by default review folder have it.
Anywise, you can get this by right-clicking the node and selecting "activate automation" from the context menu.

To begin automating, you need to know:

- **Batch mode:** shows a dry-run with a diff, in red higlights thats is remove and in green that is add. Nothing changes until you press **Run**.
- **Grouping:** Each group proposed has a header that fold/unfold on double click, inside are ordered by their new name, Further you can drag files each one groups or inside.
- **[Dictionaries](#dictionaries):** Arguably the most powerful automation tool; they dictate grouping rules and can be modified in real time, either by AI agents or manually.
- **Run on every new file:** turns the ticked automations on for every file that lands in that folder, with no dry-run. we recommend review it each automation works before active this

## Automations Methods

Each method performs a specific case, and they are applied in ascending order.

| # | Automation | What it does |
| --- | --- | --- |
| 1 | [Clean up names](#clean-up-names) | Strips hashes, site ids and noise, and moves a date written in the name to the front. |
| 2 | [Add date](#add-date) | Puts a date in front of every name, using the file's creation time when the name has none. |
| 3 | [Remove date](#remove-date) | Takes the date out of the name. |
| 4 | [Group by dictionary](#group-by-dictionary) | Moves files into folders and renames them using your [dictionary](#dictionaries). |
| 5 | [Sort by projects](#sort-by-projects) | Groups loose files that look like one project into worknodes. |
| 6 | [Remove symbols](#remove-symbols) | Removes brackets and joins what is left. |

:::note[Temporary files]
Files whose name starts with `~` are temporary files that apps hold open. No automation ever touches them.
:::

### Clean up names

- **Hashes and ids:** a long code keeps its first 4 characters, so `sample_a446087958e8…` becomes `a446`.
- **The word `sample`:** removed together with the symbol that follows it.
- **Extensions inside the name:** only the real extension stays, so `thumb.jpeg.13bc` becomes `thumb.13bc`.
- **Runs of mixed symbols:** `_~_` or `+_-` shrink to one symbol.
- **Size codes:** `Ganyu.600.3545662` becomes `Ganyu_3545`.
- **Dates:** a date written in the name moves to the front as `(yy-mm-dd)_`, or `(yy-mm-dd_hh-mm)_` when the name also has a time. Impossible dates are left alone.

These formats are recognised and cleaned:

| Kind | Example |
| --- | --- |
| Compact and ISO | `20250825`, `2025-08-25`, `20240905121359` |
| Camera prefixes | `PXL_`, `IMG_`, `VID_` |
| Screenshots | `Screenshot 2025-01-02 9.05.33 PM` |
| WhatsApp | `2026-03-09 at 16.44.50` |
| Date formats | `27 sept 2026, 11_18_05 a.m.`, `Mar 28, 2025, 03_18_41 PM`, `3 diciembre 2024` |
| Old Unix time format | `FB_IMG_1525739935595` |

### Add date

Names that already have a date get it moved to the front. Names without one get the file's creation time, always with the time: `(yy-mm-dd_hh-mm)_name`.

### Remove date

Takes the `(…)` date prefix and any date written in the name out. If both are ticked, it wins over **Add date**. A name that is only a date is kept.

### Group by dictionary

Matches the name against your dictionary, renames it by the entry and moves it to the entry's folder. See [Dictionaries](#dictionaries).

### Sort by projects

Groups loose files that look like one project into worknodes named `PJ_<title>`. In auto mode only the sure groups are made.

### Remove symbols

Runs last. It removes `( ) [ ] { }` and joins what is left, so `[Mike]_PJ.001_Web (v2).zip` becomes `Mike_PJ.001_Web v2.zip`. It also removes copy counters such as `(2)`.

## Naming convention

The automations follow this shape:

```text
(<date>)-[owner]_<topic>-<keywords> <version or (n)>
```

Keywords are any extra text in the name. Without symbols the order is the same, just without the brackets.

## Dictionaries

A dictionary sets the grouping rules that **Group by dictionary** follows to rename your files and send them to the right folder. You can change it at any time, by hand or through an [AI agent](/en/advanced/ai-integrations), and the run uses these rules.

- **Where it lives:** `<node>/.ant/dictionary.md`, a plain Markdown file that Obsidian opens fine.
- **Where it applies:** to the review folders at or below that node. A closer dictionary adds to the farther ones and replaces their entries of the same name.
- **Comments:** generated files start with a `%%` comment block that links to this page. Anything between `%%` and `%%` is a comment and is never read.

Format:
```markdown
%% Comments, ignored by the batch %%

# Single title
- <global key values>

## Entry
- `- key: values` lines refine the entry. Values are comma-separated.

### files %% files entry %%
- `- key: values` lines with exact file names grouping in the entry
```

### Keys
| Key | What it does |
| --- | --- |
| `term` | Matches the filename and is **removed** from it. |
| `[topics](#topics)` | Matches and is **kept** once in filename, written in Train-Case (`noa ushio` becomes `Noa-Ushio`). If repeats are removed the repeats. |
| `only` | Strict and **kept**: case and symbols must match exactly. |
| `exclude` | **Removed** from the filename only. |
| `pattern` | A case-insensitive regular expression, one per line. Its match is **removed**. |
| `ext` | Matches by extension, for example `.exe .msi`. |


#### `topics` 
this value can list derivatives (other forms) in parentheses:

\- topics: `value` (derivatives values), `another value` (derivatives values)
e.g. `- topics: Sakuya (Izayoi Sakuya, Sakuya Izayoi, Iza)`

rewrites every derivatives form to the value. Commas inside the parentheses do not split topics.

Short terms under 4 letters only count as a whole word or in capitals.

### Global cuts

Between the `# Title` line and the first `##` entry, a dictionary may hold only `- term:` and `- pattern:` lines.

```markdown
# Anime art
- term: sample
- pattern: [0-9a-f]{32}

## Touhou
```

- **What they do:** their text is cut from every file name, all matches, when **Group by dictionary** runs.
- **They never pick a group:** grouping reads the original names first, so a global cut cannot send a file anywhere.
- **Same kinds of text:** `term` is the same text an entry's `term` cuts. `pattern` is a case-insensitive regular expression whose match is removed, such as `[0-9a-f]{32}` for hashes.
- **Which dictionaries:** dictionaries from the storage root down to the folder all add their global cuts. The Downloads dictionary has its own.
- **Other keys:** `topics`, `only`, `ext` and `exclude` above the first entry are editor errors. `exclude` is left out on purpose: inside an entry it means "this entry does not take this file", the opposite of cutting.

### How a file is matched

The longest matching `term`, `topics` or `only` across all entries wins. `ext` and `pattern` only decide when no word matched.

### Headings

| Heading | Where the files go |
| --- | --- |
| `## Name` | A subfolder of the review folder. |
| `## Do not group` | They stay where they are but are still renamed by the entry. |
| `## NODE.Title` | A node beside the review folder, a child of the dictionary's folder. It is found by its title without the id, so reordering nodes never breaks it. |
| `## NODE^.Title` | One level up, a sibling of the dictionary's folder. |
| `## NODE^.Blue-Archive/Fanarts` | A path walks down from there. |

A node that accepts files keeps them. Otherwise they go to its own review folder, where its own automations run. Renaming a node in the app updates its `NODE` headings (only the first path segment). A `NODE` heading whose node is missing groups nothing.

#### Absolute headings

| Heading | Where the files go |
| --- | --- |
| `## @/500.HOBBIES/08.Art` | The node at that path from the storage root. |
| `## ./*.Art/*.Touhou` | A path that starts at the dictionary's folder; each `../` before it climbs one level, as in `## ../*.Art`. |

- **Segments:** each one can be the full folder name (`08.Art`) or just its title (`Art`). They match like `NODE.` headings: case-insensitive, with spaces and underscores equal to dashes.
- **Wildcard:** a segment can use `*` for any id, as in `## @/300.ACADEMIC/*.Teachnology/PJ.*_Kestrel`. The app finds the folder by the rest of the name, so ids need not be exact.
- **Same from anywhere:** unlike `NODE.` and `NODE^.`, which start at the dictionary's folder, `@/` reads the same in any dictionary.
- **Where files land:** the node files them into its review folder and runs that folder's automations.
- **Missing last folder:** only the last segment may be missing. Batch then shows that destination as "(new)" with a sparkle icon, and running it creates the folder and sends the files in.
- **What gets created:** a segment shaped like a worknode (tracker, dot, number or `*`, underscore, title, such as `PJ.*_Kestrel` or `PJ.006_Kestrel`) creates a worknode. Anything else (`*.Physics`, `Physics`) creates a node. The new folder takes the next free id or track number; only its title comes from the heading.
- **Missing earlier segment:** if any earlier segment is missing, the entry groups nothing.
- **Bare `@/`:** the editor flags a heading that is only `## @/`.

### Pinning files to an entry

Under a `## heading`, a `### files` section lists exact file names with extension, one or more per `- ` line. Several lines also work.

```markdown
## Touhou
### files
- photo.jpg, notes.pdf
```

- **It wins:** a file listed there goes to that entry whatever other rules match it.
- **Exact names:** the name must match exactly, ignoring case, so `a.jpg` and `a.png` are different.
- **One entry only:** a name is pinned to one entry only.
- **Other `###` headings:** any other `###` heading still opens an entry as before.
- **Above any entry:** `### files` before the first entry is an editor error.

In Batch mode (Grid), drag a tile, or a selection of tiles, onto another group. Its name is written under that group's `### files` in the dictionary that holds the entry. The app writes all names on one line; you can split them across lines. Groups made by **Sort by projects** take no drops.

Files dropped from another app while a batch is open land in the batch folder. Into Downloads they are copied, never moved, and a name already there is skipped. Dropped on a group, they are also pinned to it. This is the **Batch drops join their group** preference in Settings > General, on by default. Off, dropped files only land in the folder and the dictionary rules place them.

### Example

```markdown
%%
Generated by ANT. Format and keys: https://ant.mikeworld.dev/en/advanced/automations#dictionaries/
%%

# Anime art

## NODE^.Blue-Archive/Fanarts
- term: blue archive, ba
- topics: Noa Ushio, Hoshino (Takanashi Hoshino, Hoshino Takanashi)
- exclude: wallpaper
- pattern: ^ba[_-]\d+

## Touhou
- term: touhou
- topics: Sakuya (Izayoi Sakuya, Sakuya Izayoi, Iza), Remilia
- only: TH

## Installers
- ext: .exe .msi

## Do not group
- term: draft
- only: WIP
```

### The editor

The **Edit dictionary** button in the automations panel opens the file in a separate window with line numbers.

- **Autosave:** it saves as you type, even with mistakes. Opening the editor does not create the file until you type.
- **Live regrouping:** Batch mode regroups when the file changes.
- **Problems:** a problems list and a status line point at lines. Click a problem to jump to its line.

| It flags | Example |
| --- | --- |
| Unknown keys, with a suggestion | `ter` shows "did you mean `term`?" |
| A key written without a space | `-term` |
| Free text outside the format | A loose sentence between entries. |
| Empty or duplicate headings | Two `## Touhou` headings. |
| `NODE.` without a name | `## NODE.` |
| `@/` without a path | `## @/` |
| `### files` above any entry | A `### files` line before the first `##` heading. |
| Keys outside an entry | A `- topics:` line before any `##` heading. Only `term` and `pattern` are allowed there. |
| Patterns that do not compile | A broken regular expression. |
| Entries that catch nothing | An entry with no keys that can match. |
| An unclosed `%%` | A comment block with no closing `%%`. |

### Downloads

Select **DOWNLOADS**, or anything inside it, to get **Open batch** and **Edit dictionary** in the side panel.

- **One dictionary:** Downloads has a single dictionary for itself and all its subfolders. On Windows it is `%TEMP%\ANT\automations\downloads\dictionary.md`; elsewhere it sits in the system temp folder, for example `/tmp/ANT/automations/downloads`.
- **On disk:** Batch renames and moves files inside Downloads, and never overwrites an existing file.
- **Headings:** `NODE.` and `NODE^.` are ignored there, because there is no storage folder to start from. Use `@/` headings to send downloads into storage nodes.
- **No auto-run:** Downloads has no **Run on every new file**, so new downloads are never handled automatically.

AI clients can read and write dictionaries too. See [AI integrations](/en/advanced/ai-integrations).
