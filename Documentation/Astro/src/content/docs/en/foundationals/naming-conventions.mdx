A **naming convention** is a rule for naming things the same way every time, so they sort in a predictable order and are easy to find.

ANT uses three of them: **Chill Naming** and **Block Naming** for categories, and **Control Naming** for workboards and files.

## Chill Naming
Uses a two-digit incremental number (01–89), followed by a dot and a name in Train-Case (each word capitalized and joined by hyphens).

</div>

## Block Naming
Uses increments of 100 (e.g., 100, 200, 300), followed by a dot and a name in UPPERCASE.  
It is a variant of Chill Naming, ideal for top-level or broad categories.

</div>

## Control Naming
Control Naming keeps the name short: it only carries **what the item is** and **which one it is**.  
Everything else (date, area or breadcrumb, holder or client, owner, status, version, etc.) is **metadata**, and it is no longer written in the name.

> <b>TRACKING</b> _ <b>NAME</b>

| Element | Brief description |
|---------|-------------------|
| [**Tracking**](#tracking) | An [identifier](#identifiers) plus a [tracker](#tracker), e.g. `PJ.145` |
| [**Name**](#name) | A short, descriptive title in Train-Case, e.g. `Thesis-Draft` |

<Callout type="info" title="Metadata is still required">
  Removing the metadata from the name does not make it optional. The system still requires it; it is just stored [somewhere else](#where-the-metadata-lives).
</Callout>

### Control Naming (for Folders)
Used by [Workboard Nodes](/en/foundationals/workboard-nodes), it was designed for quick recognition and easy filtering between projects.

```fs title="Use example" ins="PJ.145" ins="HW.024" ins="CR.015"
📁 PJ.145_Thesis-Draft
📁 HW.024_Electromagnetism-Research
📁 CR.015_Sketching-For-Storyboards
```

The folder's metadata lives in the [ANT database and its `.ant/info.json`](#folders-database-and-antinfojson).

### Control Naming (for Files)
Used by **files**; their main purpose is to organize, filter and identify.  
A file follows the same shape: a short [identifier](#identifiers-for-files) of the kind of document, an underscore and its [name](#name-for-files).

```fs title="Root/100.PERSONAL/01.Documents/02.Finance" ins="FST" ins="CNT"
📄 CNT_Mortgage-Contract-Houston.pdf
📄 FST_Bank-Statement-March-2023.pdf
📄 FST_Bank-Statement-April-2023.pdf
📄 FST_Bank-Statement-May-2023.pdf
```

The file's metadata goes into the [file properties](#files-file-properties), not into its name.

<Callout type="warning" title="Not automated yet">
  FolderManager does not write metadata into file properties yet. Until it does, add it by hand from the file's properties dialog or the app that created the file.
</Callout>

## Where the Metadata Lives

### Folders: Database and .ant/info.json
Each storage keeps its metadata in two places, both managed by FolderManager:

- **The ANT database**: `.ant/ant.db` at the storage root. It holds the tree of nodes (name, type, status) and a copy of every folder's metadata, so searches never have to open the folders. A new storage is seeded from `Tree.yaml`.
- **The folder's own `info.json`**: a hidden `.ant/` folder inside the folder holds `info.json`, the metadata that travels with the folder when it is moved or copied.

```json title="PJ.145_Thesis-Draft/.ant/info.json"
{
  "owner": "Mike Diaz",
  "created": "24-06-01",
  "status": "in-progress"
}
```

| Key | Meaning |
|-----|---------|
| `owner` | Who the workboard belongs to. `holder` and `client` are read as the same field. |
| `created` | Start date, in the short `YY-MM-DD` form. |
| `status` | `in-progress`, `for-review`, `hold` or `done`. |
| `favorite` | `true` when the folder is marked as a favorite. |

Any other key you add (for example a breadcrumb or a deadline) is shown in the folder details and can be searched.

<Callout type="danger" title="Don't edit or delete .ant/ by hand">
  The `.ant/` folder belongs to FolderManager. It also holds the folder's lasting id (`dragpath.json`), which lets the app recognise a folder moved outside of it.
</Callout>

### Files: File Properties
For files, the metadata is injected into the file's own properties: document properties (author, title, subject, tags, comments) or media properties (tags of images, audio and video).  
That way the name stays short, the metadata travels inside the file, and the operating system's search can still find it.

| Metadata | Example property |
|----------|------------------|
| [Holder](#holders-and-clients) | Author / Owner |
| [Date](#date-and-timestamps) | Date or Comments |
| [Breadcrumb](#breadcrumbs) | Subject / Tags |

### What FolderManager Covers
FolderManager automates these rules so you don't apply them by hand. Some are covered today, others are not yet.

| Rule | FolderManager |
|------|---------------|
| Next tracker for a new workboard (`PJ.NNN_New-Workboard`) | ✅ Yes |
| Keeps the tracking part fixed when renaming a workboard | ✅ Yes |
| Recognises `PJ.`, `PR.` and `HW.` folders as workboards | ✅ Yes |
| Recognises `TK.` and `CR.` folders as workboards | ❌ Not yet |
| Creates `.ant/info.json` with `owner` and `status` for new workboards | ✅ Yes |
| Indexes the database and `info.json` fields for search | ✅ Yes |
| Writes metadata into file properties | ❌ Not yet |

## Elements of Naming Conventions

### Tracking
The tracking part is the [identifier](#identifiers) joined by a dot to the [tracker](#tracker): `PJ.145`.  
It tells at a glance what kind of item it is and in which order it was created.

### Identifiers
The identifier is a **two-letter code** that identifies the type of workboard.  
The official identifiers are:
- `PJ`: Project
- `PR`: Practice
- `HW`: Homework
- `CR`: Course
- `TK`: Task

<Callout type="info" title="Support in FolderManager">
  FolderManager recognises `PJ.`, `PR.` and `HW.` as workboard identifiers today, and new workboards start as `PJ.`. `CR.` and `TK.` are not handled by the app yet.
</Callout>

### Identifiers (for Files)
For files, the identifier is a short uppercase code for the **kind of document**, chosen to fit each folder.

```fs title="Use example" ins="FST" ins="CNT" ins="INV"
📄 FST_Bank-Statement-March-2023.pdf ← Financial statement
📄 CNT_Mortgage-Contract-Houston.pdf ← Contract
📄 INV_Web-Design-Services.pdf ← Invoice
```

Files with the same identifier sort together, so a contract never ends up between bank statements.

### Tracker
The tracker is a sequential index that provides chronological order and simple referencing.  
> While many systems can sort by date, a tracker provides a quick way to follow progress without relying on timestamps.

Used in tandem with the identifier, it instantly communicates the type and order of the workboard.

```fs title="Use example" ins="PJ.005" ins="PJ.006" ins="HW.015" ins="HW.016"
📁 PJ.005_Tutorial-Organize-Documents ← for projects
📁 PJ.006_Sales-Landing-Page

📁 HW.015_Grammar-Essay ← for school homework
📁 HW.016_Grammar-Review
```

<Callout type="warning" title="Only need 3-digit counters">
  As [workboard nodes](/en/foundationals/workboard-nodes) are temporary and meant to be eventually stored or removed, **3-digit counters are recommended**: they allow up to 999 items per type. FolderManager keeps counting past 999 (`PJ.1000`) instead of resetting.
</Callout>

### Name
The name is a short, descriptive label that identifies the content or focus of the item; in other words, its title.  
Use <u>Train-Case</u> (words capitalized and joined by hyphens) to keep it readable and free of spaces.

```fs title="Use example" ins="Landing-Page-Redesign" ins="Environmental-Law-Essay" ins="How-To-Organize-Documents"
📁 PJ.001_Landing-Page-Redesign
📁 HW.002_Environmental-Law-Essay
📁 PJ.003_How-To-Organize-Documents
```

### Name (for Files)
A file name follows the same rule, and it must be unique inside its folder.  
If two files would only differ by a date or a version, that difference is part of what the file is, so it belongs in the name:

```fs title="Use example" ins="March-2023" ins="April-2023"
📄 FST_Bank-Statement-March-2023.pdf
📄 FST_Bank-Statement-April-2023.pdf
```

### Date and Timestamps
Although labeled as "Date", this element works like a flexible timestamp that adapts to context. It is metadata: store it in `created` (folders) or in the file properties (files).

> It helps to see important times such as deadlines, milestones, start dates, periods or seasons.

<h5> You may use these formats: </h5>
- `YY-MM-DD` (Year-Month-Day): **most common**, used for start dates, deadlines, deliveries, etc.
- `YY-MM` (Year-Month): for monthly tracking, reports or retainers.
- `YY-QQ` (Year-Quarter): for financial quarters.
- `YY-V.1`, `YY-V.2` (Year-Version): for versions or iterations.
- `YY-U1` or `YY-C1` (Year-Unit/Chapter): for units or chapters in educational contexts.
- `9G`, `10G`, `12G` (Grade): for school grades; 9th grade, 10th grade, 12th grade.
- `S2`, `S3`, `S4` (Semester): for school semesters, often used in curriculum tracking.

### Breadcrumbs
A breadcrumb defines the contextual type of the workboard, usually based on the parent folder's category. It is metadata, so it acts like a category tag you can search by, without creating more levels.

### Holders and Clients
The holder identifies who the workboard belongs to (client, brand, organization, school, owner). It is stored as `owner` (folders) or as the author or owner property (files).

> It provides ownership context and is especially useful when managing multiple clients or people.

<Callout type="warning" title="Recommendation">
  Avoid names that are too long or complex (e.g. "W&M-Laws" instead of "College-of-William-&-Mary-Law-School").
</Callout>

If you need to keep confidentiality or privacy, use a pseudonym together with a client list document saved somewhere else (e.g. `C-018-Ara` for Aradir, client no. 18).
