## Level 1
The first level lies directly inside the storage root.  
This means that we are talking about the **principal categories** that define the content of each [node](/foundationals/core-concepts#nodes).

<h5> Naming Convention: </h5>
> **Sequence Chill Naming:** Employ an incremental numbering of 3 digits in a sequence of 100, followed by a dot, and their name in UPPERCASE (Capitals).

```css {2-4}
 📁 Root
  ├── 📁 100.PERSONAL
  ├── 📁 200.WORK
  ├── 📁 300.PROJECTS
```

<Callout type="danger" title="Only be named once">
  This is defined the first time and should not be renamed again to prevent any conflicts with programs with linked paths, dependencies or shortcuts.
</Callout>

<h5> Key points: </h5>
- **Storage** This level must not contain files, external folders, or unorganized content. It should only include [nodes (folders)](/foundationals/core-concepts#nodes) considered as main categories defining their own content.
- **Support Nodes:** These reserve the sequence 900 combined with their identifier (e.g. 998.Review
instead of 98.Review).

##### Recomendation for the Level 1:

```css {2-9}
 📁 Root
  ├── 📁 100.PERSONAL
  ├── 📁 200.WORK
  ├── 📁 300.PROJECTS
  ├── 📁 400.ACADEMIC
  ├── 📁 500.HOBBIES
  ├── 📁 900.Resources
  ├── 📁 998.Review (Index)
  └── 📁 999.Settings
```

## Level 2
The second level is a child of a [Level 1](#level-1) node, these must use subcategories of the parent class.  
This means that we are talking about the areas, subjects, types of job, or another group related their parent node.

<h5> Naming Convention: </h5>
> **Chill Naming:** Employ an incremental numbered (01-89), followed by a dot and each one node use Train Case.

```css {3-4, 7}
 📁 Root
  ├── 📁 100.PERSONAL
  │    ├── 📁 01.Documents
  │    ├── 📁 02.Gallery
  │    └── 📁 . . .
  ├── 📁 200.WORK
  │    ├── 📁 01.Development
  │    └── 📁 . . .
```

<Callout type="warning" title="Keep names without duplicates or redundant">
  Avoid duplicate names or semantically related names that just could be separated further in the next level.
</Callout>

<h5> Key points: </h5>
- **Storage** This level must not contain files, external folders, or unorganized content. It should only include [nodes (folders)](/foundationals/core-concepts#nodes) considered as subcategories of the parent defining their own content.
- **Support Nodes:** These have reserve sequences "90-99" and "00" for their identifiers.

## Level 3
The third level is a child of a [Level 2](#level-2) node, **supports additional organization**, either through category extensions or [**Workboard Nodes**](/foundationals/workboard-nodes) **(folders)**.

<h5> Naming Convention: </h5>
You can use 2 naming conventions;  
**1.-** If you need extend *with subjects, topics, more categories,* use the `Chill Naming` yet.  
> **Chill Naming:** Employ an incremental numbered (01-89), followed by a dot and each one node use Train Case.

```css {4-6}
 📁 Root    
  ├── 📁 100.PERSONAL
  │    ├── 📁 01.Documents
  │    │    ├── 📁 01.Personal
  │    │    ├── 📁 02.Finantials
  │    │    ├── 📁 03.Legals
  │    │    └── 📁 . . .
  │    ├── 📁 02.Gallery
  │    └── 📁 . . .
```

**2.-** If the you need manage it *for tasks, projects, etc.** use the `Control Naming` Convention.  
> **Control Naming:** Use the parent node name, followed by a dot and each one node use Train Case.

```css {5, 8-9}
 📁 Root    
  ├── 📁 100.PERSONAL
  ├── 📁 200.WORK
  │    ├── 📁 01.Development
  │    │    ├── 📁 PJ.006_(23-03-03) Landingpage [Wallter-White]_Astro Carwash 
  │    │    └── 📁 . . .
  │    ├── 📁 02.Video-Edition
  │    │    ├── 📁 PJ.130_(25-07-03) Tutorial [MikeWorldYt]_Organize Documents
  │    │    ├── 📁 PJ.131_(25-07-03) Review [Isa-Marcial]_Huawei pura 70 
  │    │    └── 📁 . . .
```
