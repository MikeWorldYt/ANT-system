## Level 1
The first level lies directly inside the storage root.  
They are the **principal categories** that define the general purpose of each [node](/foundationals/core-concepts#nodes).

<h5> Naming Convention: </h5>
Employ an incremental numbering of 3 digits in a sequence of 100, followed by a dot (.), and their name in UPPERCASE (Capitals).

```css {2-4}
 📁 Root
  ├── 📁 100.PERSONAL
  ├── 📁 200.WORK
  ├── 📁 300.PROJECTS
```

<Callout type="danger" title="Only be named once">
  This is defined the first time and should not be renamed againto prevent any conflicts with programs with linked paths, dependencies or shortcuts.
</Callout>

##### Key points for the Level 1:
- **Define Categories:** Each node serve to assign and group modules for the next level, In that way, It must be global and highly descriptive. Each category define their content.

- **Content:** This level shouldn't files or external folders or unorganized.

- **Support Nodes:** These have reserved the sequence 900, beside mix with their own identifier. e.g. 998.Review
instead 98.Review.

##### Recomendation for the Level 1:

```css {2-9}
 📁 Root
  ├── 📁 100.PERSONAL
  ├── 📁 200.WORK
  ├── 📁 300.PROJECTS
  ├── 📁 400.ACADEMIC
  ├── 📁 500.HOBBIES
  ├── 📁 900.Resources
  ├── 📁 998.Review (Index)
  └── 📁 999.Settings
```

## Level 2
The second level is a child of a [Level 1](#level-1) node, then should use a subcategorie to the parent.  
These means areas, subjects, types of job, or another group related their parent node.

<h5> Naming Convention: </h5>
Employ an incremental number system (01-89), followed by a dot (.) and each one node use Train Case.

```css {3-5, 7-9}
 📁 Root
  ├── 📁 100.PERSONAL
  │    ├── 📁 01.Documents
  │    ├── 📁 02.Gallery
  │    └── 📁 . . .
  ├── 📁 200.WORK
  │    ├── 📁 01.Development
  │    └── 📁 . . .
```

##### Key points for the Level 2:
- **Defined Subcategories:** Each node serve to assign and group modules for the next level, In that way, It must be global and highly descriptive.
